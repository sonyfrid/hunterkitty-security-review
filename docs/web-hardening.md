# CSRF, CORS и заголовки безопасности

Проверено 18.11.2026 запросами GET к стенду и к боевому адресу (только чтение, без авторизации).

## CSRF: не применимо, и почему
CSRF работает, когда браузер сам прикладывает к запросу учётные данные: cookie или HTTP-авторизацию. В HunterKitty их нет:
- API не ставит и не читает cookie, серверных сессий на cookie нет;
- пользователь определяется только по заголовку `X-Telegram-Init-Data`, который страница добавляет сама из `window.Telegram.WebApp.initData`;
- чужой сайт не может заставить браузер прислать этот заголовок: форма или `<img>` его не добавят, а `fetch` с нестандартным заголовком требует CORS-разрешения, которого нет (ниже).

Поддельный запрос с чужого сайта приходит без заголовка и получает 401. Если когда-нибудь появятся cookie-сессии (см. план в HK-11, там выбран заголовок, а не cookie), понадобятся `SameSite=Strict` и CSRF-токен.

## CORS: разрешений нет, так и задумано
- Ни один ответ API не содержит `Access-Control-Allow-Origin`.
- Предварительный запрос `OPTIONS` с `Origin: https://evil.example` и заголовком `X-Telegram-Init-Data` получает 401 без CORS-заголовков. Браузер блокирует такой запрос с чужого сайта.
- Mini App и API живут на одном адресе, CORS им не нужен.

## Заголовки на страницах Mini App и ответах API
| Заголовок | Значение | Зачем |
|---|---|---|
| `Content-Security-Policy` | `default-src 'self'`; скрипты только свои и `telegram.org` плюс хэш одного встроенного обработчика; `connect-src 'self'`; `object-src 'none'`; `base-uri 'self'`; `form-action 'self'` | XSS не может подгрузить чужой скрипт или отправить данные на чужой сервер |
| `frame-ancestors` (в CSP) | `'self' https://web.telegram.org https://*.telegram.org` | встроить страницу во фрейм может только сам сайт и веб-версия Telegram (защита от clickjacking, вместо `X-Frame-Options`) |
| `X-Content-Type-Options` | `nosniff` | браузер не угадывает тип файла |
| `Referrer-Policy` | `strict-origin-when-cross-origin` | адрес страницы не уходит на сайты вакансий |
| `Cache-Control` | `no-store` | личные данные не оседают в кэше Telegram на телефоне |

`style-src 'unsafe-inline'` оставлен сознательно: интерфейс задаёт стили атрибутом `style`. Скрипты inline запрещены, поэтому риск ограничен.

## Что улучшить
| Что | Риск | Рекомендация |
|---|---|---|
| Нет `Strict-Transport-Security` | Low: первый заход по `http://` можно перехватить. В Telegram ссылка всегда `https://`, поэтому реальный риск мал | добавить в обратном прокси `Strict-Transport-Security: max-age=31536000; includeSubDomains`, когда появится свой домен |
| Заголовок `Server` раскрывает версию веб-фреймворка | Informational: помогает подобрать известные уязвимости версии | убрать или заменить в обратном прокси |
| Страница AI-помощника на собеседовании (отдельный сервис на том же адресе) отдаёт ответ без CSP и `nosniff` | Low: страница своя, внешних скриптов нет | добавить те же заголовки в middleware сервиса или в обратном прокси для всего адреса |
