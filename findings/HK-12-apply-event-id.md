# HK-12. Событие «Откликнуться» принимает чужой номер строки выдачи

| | |
|---|---|
| Категория | OWASP API Top 10: API1 Broken Object Level Authorization (без утечки данных) |
| Серьёзность | Informational, CVSS 3.1 ≈ 0 (данные не раскрываются и не меняются) |
| Компонент | API Mini App, маршрут статистики нажатий «Откликнуться» |
| Кто нашёл | негативный API-тест по всем маршрутам, 18.11.2026 |
| Статус | открыто, исправление в плане |

## Что не так
Кнопка «Откликнуться» открывает сайт работодателя, а сервер только записывает событие для статистики. Номер строки выдачи в адресе не проверяется на владельца: можно записать событие с номером чужой строки.

## Чем опасно
Ничем, кроме точности статистики. Ответ всегда `{"ok": true}`, данные чужой вакансии не возвращаются, чужой сейф и выдача не меняются. Событие записывается от имени того, кто нажал. Остальные маршруты с номером строки (открыть, перейти, сохранить, письмо) проверяют владельца и отвечают 404, это закрыто тестами.

## Как исправить
Перед записью события проверить, что строка принадлежит пользователю, тем же запросом, что у остальных маршрутов, и отвечать 404 на чужую.

## Проверка
`hunterkitty-e2e/tests/api/access.spec.js`, тест IDOR: сейчас фиксирует фактическое поведение (ответ без данных), после исправления ожидание сменится на 404.
