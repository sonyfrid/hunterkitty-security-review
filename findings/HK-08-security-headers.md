# HK-08. У страницы Mini App не было заголовков безопасности

| | |
|---|---|
| Категория | OWASP Top 10: A05 Security Misconfiguration |
| Серьёзность | Low, CVSS 3.1 ≈ 3.1 (AV:N/AC:H/PR:N/UI:R/S:U/C:L/I:N/A:N) |
| Компонент | веб-сервер Mini App |
| Кто нашёл | аудит 11.11.2026, проверено живьём на стенде |
| Статус | исправлено 17.11.2026 |

## Что не так
Не было `Content-Security-Policy`, `X-Content-Type-Options`, защиты от встраивания в чужие фреймы и `Referrer-Policy`.

## Чем опасно
Если где-то проскочит XSS, без CSP его ничто не остановит. Без запрета фреймов страницу можно встроить в чужой сайт.

## Как исправлено
Заголовки на каждый ответ:
- скрипты только свои и `telegram.org`, плюс хэш одного встроенного обработчика;
- `connect-src 'self'`, `object-src 'none'`, `base-uri 'self'`;
- `frame-ancestors` только сама страница и веб-версия Telegram (она открывает Mini App во фрейме), поэтому вместо `X-Frame-Options` используется CSP;
- `nosniff`, `strict-origin-when-cross-origin`.

## Проверка
Все 39 E2E-тестов Mini App прошли с новыми заголовками, в консоли браузера ни одного нарушения CSP. Проект с E2E: github.com/sonyfrid/hunterkitty-e2e.

## Вывод
CSP надо собирать под реальную страницу: сначала посмотреть, что она грузит, и только потом закрывать. Иначе сломаешь приложение у всех пользователей.
