# HunterKitty: разбор безопасности своего продукта

Я сделал HunterKitty, Telegram-бот и Mini App для поиска работы. Около 230 пользователей, Python, PostgreSQL, ИИ-письма на LLM. Потом проверил его как атакующий: искал уязвимости, оценивал реальный риск, исправлял и закрывал каждую находку тестом.

Здесь все находки с разбором и запускаемые демо: для каждой есть уязвимая и исправленная версия кода и тесты. На уязвимой версии тесты показывают баг (`xfail`), на исправленной проходят.

Код самого продукта закрыт, поэтому в демо вынесены только нужные функции в упрощённом виде.

## Границы
- Только свой продукт.
- Атаки только на изолированном стенде: локальная копия, фальшивый токен бота, локальная модель (Ollama). Боевой сервис и настоящих пользователей не атаковал.
- В отчётах нет готовых наборов нагрузок, только суть, риск и исправление.

## Как работал
- Модель угроз: кто может влиять на данные (работодатели и авторы постов, пользователи Mini App, внешние сайты) и куда эти данные попадают.
- Проверка по OWASP Top 10, OWASP API Security Top 10 и OWASP Top 10 for LLM Applications.
- Ручные проверки в Burp Suite на стенде.
- Свои red-team тесты на pytest против кода продукта на стенде.
- Разбор кода: авторизация, доступ к данным, внешние запросы, лимиты.
- Для каждой находки: воспроизведение, оценка серьёзности (CVSS 3.1), исправление, тест-регрессия.

## Что выдержало проверку
- Все 31 маршрут API без подписи Telegram отвечают 401.
- Подделка initData: мусор, чужой токен, просроченная строка, дата из будущего, подмена id пользователя после подписи. Везде отказ.
- Доступ к чужим данным (IDOR): второй пользователь не может открыть, сохранить или составить письмо к чужой вакансии (404), чужой счёт не находится.
- XSS: вакансия с HTML и скриптами в названии, компании и описании показывается как текст, ничего не исполняется.
- Обход путей у статики и попытки достать файлы настроек: ничего не отдаётся.
- Флуд-контроль: частые запросы получают 429, отзывы ограничены по частоте.
- Загрузка резюме: слишком большой файл, zip-бомба, поддельный PDF и не то поле дают 400, огромный текст разбирается быстро.
- Отзывы пользователей приходят администратору с экранированным HTML.

## Известные низкие риски
Остались две мелочи с низким риском: одна про лишние записи в базу при частых запросах, вторая про обработку сбоя платёжного провайдера. Платежи сейчас выключены. Обе в плане работ.

## Запуск
```bash
pip install -r requirements.txt
pytest -v -rx          # Python-демо: HK-01..HK-06
node --test js/openUrl.test.js   # HK-07
```
Тесты запускаются в GitHub Actions на каждый push.
